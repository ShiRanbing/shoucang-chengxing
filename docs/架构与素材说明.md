# 架构与素材说明

## 架构

浏览器状态是唯一数据来源：用户操作更新 Project，随后重绘表单/卡片、Canvas 和延迟500ms的本地存储。

模块划分：

- model：Project 构造、示例数据、稳定排序、输入验证、链接白名单。
- sources：用户提供的截图来源描述及固定本地资源清单。
- notes：22篇原创笔记（杭州10、上海6、日常6）、独立封面路径、内容类型、城市和固定地点引用，全部本地数据。
- community：发现页、筛选与搜索、笔记详情、两类收藏按钮和进入工作台入口。
- guide：首次进入发现页的四步引导卡、可重复打开的使用指南、按行程状态更新的下一步提示。关闭偏好使用独立的 `shoucang-chengxing.guide.v1` 本地键，不写入 Project，不随项目 JSON 迁移；存储不可用时仍保留当前页面内的选择。城市入口只改变社区搜索，不修改行程，偏好整理复用原有确认逻辑。
- landmarks：14个已收录地点的城市、名称与别名白名单，匹配42张本地景点图，不按类别合并不同地点。
- assets：优先加载景点独立插画，按需缓存；未知地点或加载失败使用两城各三套类别图集替代。
- icons：本地SVG导航、搜索、普通收藏与旅行行李箱图标；品牌图标内嵌在HTML。
- renderer：纸张、标题、路线编号、文字换行和1—6站布局。独立编号与时间栏按插画居中排列，跨行路线沿外侧留白连接；同一份数据根据主题绘制水彩晕染、彩铅排线或复古拱形底色。城市印章、纸角、胶带便签与页脚装饰由Canvas即时绘制，不增加图片依赖，预览与导出共用完整画面。
- app：DOM交互、状态更新、确认对话框、草稿和文件导入导出。

入口是静态 HTML。样式用 Tailwind CLI 本地编译，部署无运行时依赖。独立预览文件是同一份模块源码与资源内嵌的构建产物，不维护第二套业务逻辑。

### 数据约定

Project v1 包含 city/title/date/theme/preferences/inspirations/stops、community 和 otherTrips。community.savedNoteIds 允许全部22篇笔记，community.travelNoteIds 只允许16篇旅行笔记。日常笔记没有旅行收藏入口，数据层也拒绝放入旅行收藏。旧文件缺少新增字段时按杭州项目补齐。

Inspiration 包含 city，并保留 sourceUrl 和可选 sourceRef，后者只能引用 sources 中固定的来源ID。示例使用 isExample=true 表示演示设置，不代表来源虚构。全部收藏灵感统一保存，工作台按当前 city 过滤；整理和手动选站均不能跨城。

当前城市行程由 Project 的 title/date/stops 唯一表示。切换城市时将它存入 otherTrips，再取出目标城市草稿并从 otherTrips 移除，避免两处维护同一行程副本。otherTrips 只包含非当前城市的 title/date/stops；偏好与视觉风格为项目共用。取消旅行收藏会同时清理当前和暂存城市中的悬空站点，涉及任一行程时先确认。JSON包含两城完整草稿，校验城市、日期、引用及每城六站上限。

旅行收藏使用固定的笔记到地点映射，不自动请求原帖。带入的地点使用 community: 前缀ID去重。多篇笔记引用同一地点时只有一张候选卡，来源列表由当前旅行收藏推导。增删旅行收藏不会自动安排当天行程；取消最后一个地点来源时才移除该候选和其行程站点，涉及已有行程先提示确认。普通收藏不影响地点集合。编辑过的地点理由、必去标记、备注和时长在来源仍存在时保留。

JSON导入校验笔记ID白名单、重复ID及候选关联一致性。社区候选可编辑，但删除由其来源旅行收藏统一管理；手动新增的地点仍可独立删除。首次在已有旧草稿上添加旅行收藏时确认开启新路书，普通收藏保留，旧草稿可事先备份。

Stop 引用 Inspiration ID，minutes 允许0（留白）至720整数。note=null 表示跟随心动理由；note="" 表示用户主动清空，后续不自动补回。

导入时检查字段、版本、日期、长度、重复ID、行程引用、六站上限和60份收藏上限；重新构造允许字段，不接纳任意图片路径或外部资源。

### 偏好整理

仅整理当前城市的候选。慢逛3站、紧凑5站。先按必去排序，再按类别是否命中兴趣排序；同分保持原始收藏顺序。必去超过默认数量时扩展到必去数量，超过6个报错。重整时保留仍入选地点的备注和停留时长，需先确认覆盖顺序。

发现页初始混合展示全部内容；搜索匹配城市、标题、摘要、标签和地点名称。输入或点击杭州/上海会得到对应城市的旅行内容；快捷城市按钮会重置收藏和主题筛选，避免筛选叠加造成空结果。普通关键词没有匹配时显示支持城市的提示。清空关键词恢复当前收藏视图内的全部主题。

### 渲染与失败处理

三种主题均使用1080×1440画布。1—2站单列，3—4站两列两行，5—6站两列三行，沿蛇形编号连接。固定纸张噪点确保同一数据渲染稳定。预览/下载共用Canvas，不通过页面截图生成PNG。

每站预留独立的编号和停留时间栏，标签有纸色底与时钟图形，图片从标签下方开始。布局先测量地点名和备注的实际换行高度，再计算插画可用尺寸；同排两站采用较小的共同尺寸，保持图片及地点名首行对齐。长标题会向下移动内容起点，0分钟显示“随心停留”，最长720分钟标签按文字宽度扩展。连接线从标签间的空白和列间沟槽通过，避免穿过图片与文字。

主题加载有超时和失败替代；渲染使用递增版本号，快速切换时旧请求不能覆盖新主题。保存失败仅提示，不清空当前状态。JSON错误不覆盖现有项目。用户文本使用textContent，不拼接进HTML。

景点图由城市与规范化名称匹配（允许明确收录的别名、空格与分隔点差异），不使用模糊包含匹配，避免“西湖旁的餐馆”误配西湖。旧示例ID、社区前缀ID和手动输入同一已知地点得到相同图片；把地点改成未知名称时会回到类别图，不沿用旧ID的景点。JSON无需新增资源字段，旧备份可直接使用。卡片与Canvas共用这一映射，保留透明边缘并等比绘制，不裁掉地标。

当前14个内置地点均有三种风格的独立图，共42张。用内置 imagegen 逐景点逐风格生成透明PNG，浏览器Canvas仅做等比768px透明WebP编码；最终资源随包提供于 `public/assets/place-<景点key>-<主题>.webp`。中文提示词全集在 `docs/景点插画提示词.json`，原图副本在本地 `assets-staging/place-originals/`。运行时不调用图像模型。

景观与体验均为风格化表达；尤其茶馆、文创店、餐厅使用原帖描述的体验意象，不承诺精确还原商家建筑。下面的旧类别图集继续作为未知地点与失败场景的后备资源，内置地点正常加载时不使用它们。

三张原创AI插画图集由内置图像工具生成，每张1024×1536，2列×3行，每格512×512。类别顺序为：第一行自然/街巷，第二行人文/美食，第三行茶咖/其他。三套文件分别为watercolor-atlas.png、pencil-atlas.png、retro-atlas.png。

图片代表通用风景或体验类别，不是指定店铺外观。程序在Canvas中按格裁取，原图未做外部图像编辑。水彩与复古保留透明通道，彩铅保留纸底并在画布中采用multiply融合。

完整生成提示词保存在 `docs/插画生成提示词.json`；页面和导出文字由程序绘制，与插画分离以保持可编辑和清晰。

本轮增加22张独立AI创作社区封面，均为一篇一图。用内置 imagegen 分别生成，再使用浏览器 Canvas 做800px JPEG编码以减少部署体积，没有调用运行时模型。提示词在 `docs/社区封面提示词.json`，包内路径为 `assets/cover-<笔记ID>.jpg`。封面不是实景照片，来源在笔记详情说明。

上海新增三张1024×1536图集：`shanghai-watercolor-atlas.png`、`shanghai-pencil-atlas.png`、`shanghai-retro-atlas.png`，仍按自然/街巷/人文/美食/茶咖/其他的固定顺序，表现江景天际线、梧桐街区、园林、小笼包、咖啡和旅行小物。中文提示词在 `docs/上海插画提示词.json`。杭州与上海按城市选择素材，合计36幅类别插画。
